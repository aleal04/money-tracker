# Espacios y periodos flexibles — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add "espacios" (separate money buckets with their own period frequency, adjustable dates, running balance) and connected transfers between espacios to the existing Laravel money tracker.

**Architecture:** Same ssi layering as the rest of the app (Controller+Contract → FormRequest → readonly DTO → Service+Contract → Repository/QueryRepository → Model). Pure date/money rules live in helpers/calculators with unit tests. Periods move from (Year, Month, Half) to (FkSpace, StartDate, EndDate). Schema lives in `database/scripts` (no migrations) + the sqlite test schema trait.

**Tech Stack:** unchanged (Laravel 12, Inertia 3, Vue 3 TS, SCSS, MySQL scripts, PHPUnit sqlite, Vitest).

**Spec:** `docs/superpowers/specs/2026-11-18-espacios-design.md` (binding; §8 + §8b decisions). Base rules: `docs/superpowers/specs/2026-11-18-money-tracker-laravel-design.md`, `CLAUDE.md`.

## Global Constraints

- Follow `CLAUDE.md` exactly (ssi naming: PascalCase tables/columns, Id<Table>/Fk<Ref>, audit columns, logical delete via LogicalDeleteTrait; scripts idempotent with NO dynamic SQL; PHPDoc on every method; forbidden folders; Spanish UI, English code).
- Every schema change goes to BOTH `database/scripts/**.sql` and `tests/Concerns/CreatesSchemaTrait.php`; keep `MysqlScriptTest` green.
- Money in integer céntimos; no floats. Dates as `Y-m-d` strings in JSON (`startDate`, `endDate`), app timezone America/Costa_Rica.
- Existing JSON keys stay; new keys are additive (frontend keeps working between tasks).
- Frequencies: `weekly | biweekly | monthly | custom` (+ `CustomDays` for custom). Template frequencies: `cada_periodo | mensual_repartido | mensual_dia` (+ `DayOfMonth` 1–31 for mensual_dia). Line source adds `transfer`.
- Space selection is passed explicitly by the frontend (`space` query param / `spaceId` body field); when omitted, the primary space is used (keeps old calls working).
- The Excel parity tests (I Quincena Octubre: egreso 49309600, disponible 6453600, falta 3090000) must keep passing in the Salario (primary, biweekly) space.
- Commits end with a blank line then `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Don't touch the user's `mysql` container or `.env` DB values. Leave uncommitted markdown edits in IDEAS.md/docs alone.

## Review Focus

1. Balance chain correctness with arrastre (no double count), negative remaining, edits in an old period propagating — Tasks 1, 4.
2. Transfer propagation on pay/unpay/amount edit/delete/close-carry/reopen, all in one transaction, never orphaned destination lines — Task 5.
3. Period projection edge cases: month ends, February/leap year, weeks crossing months, adjusted dates, gaps, overlaps rejected — Tasks 1, 3.
4. Monthly split across 1/2/4/5 periods with céntimo remainders (templates and cuotas) and cuotas advance on the first period of a new month — Tasks 1, 3.
5. Deleting espacios: blocked unless empty; primary undeletable; exactly one primary — Task 4.

### Task 1: Pure calculators — period schedule, monthly split, balance chain

**Files:** `app/Helpers/PeriodScheduleHelper.php`, extend `app/Helpers/MoneyHelper.php`, extend `app/Services/Template/TemplateExpander.php`, new `app/Services/Period/BalanceCalculator.php`, `app/Constant/{SpaceFrequencyConstant.php}` and update `TemplateFrequencyConstant`, `LineSourceConstant` (`TRANSFER`); tests in `tests/Unit/`.

**Interfaces:**

- `PeriodScheduleHelper::proposeNext(string $frequency, ?int $customDays, ?string $lastEndDate, string $today): array{start:string,end:string}` — biweekly: calendar halves (1–15, 16–EOM) when the start is the 1st or 16th, else start+14; monthly: to EOM when start is the 1st, else start + 1 month − 1 day; weekly: start+6; custom: start+customDays−1; first period (no last): the period containing `$today` aligned to the frequency (weekly/custom start today).
- `PeriodScheduleHelper::label(string $frequency, string $start, string $end): string` — "I Quincena Octubre 2026" / "II Quincena Octubre 2026" (biweekly aligned halves), "Octubre 2026" (monthly aligned), "Semana 12–18 nov 2026" (weekly), "12 nov – 26 nov 2026" (custom or non-aligned; cross-year shows both years).
- `PeriodScheduleHelper::periodsStartingInMonth(string $frequency, ?int $customDays, string $anyStartInMonth): int` — projected count for the month (biweekly 2, monthly 1, weekly 4|5, custom by projection).
- `MoneyHelper::splitAcross(int $cents, int $parts, int $index): int` — equal parts, remainder céntimos to the first parts (index 0-based); `splitMonthly` stays as `splitAcross($c, 2, $half-1)`-compatible (ceil first).
- `TemplateExpander::expand(iterable $templates, array $period /* frequency, customDays, start, end, indexInMonth, partsInMonth */): array` with new frequencies (`mensual_dia` matches if DayOfMonth ∈ [start,end] days of that month; clamp to EOM).
- `BalanceCalculator::chain(int $initialBalance, iterable $periodsSummaries /* ordered: ingreso, egreso */): array<array{saldoAnterior:int,restante:int}>`.

- [ ] **Step 1:** Unit tests first: biweekly from 2026-10-15 end → next 2026-10-16..2026-10-31; from 2026-02-15 → 2026-02-16..2026-02-28; 2028-02 leap → ..29; monthly aligned/non-aligned; weekly crossing month; custom 10 days; labels incl. cross-year; periodsStartingInMonth weekly for a 5-week month; splitAcross(100001,4,i) sums back; mensual_dia 31 in a 30-day month clamps; chain with negatives and arrastre-excluded egreso.
- [ ] **Step 2–4:** RED → implement → GREEN (`php artisan config:clear && php artisan test --testsuite=Unit`).
- [ ] **Step 5:** Commit `feat: period schedule, monthly split and balance calculators`.

### Task 3: Flexible periods — create with any frequency, adjust dates, overlap/gap rules

**Files:** Period controller/requests/DTOs/service/repositories; tests `tests/Feature/Period/FlexiblePeriodTest.php`.

Endpoints: `POST /periods/store {spaceId, startDate, endDate}`; `POST /periods/next {spaceId}` (uses proposeNext); `PUT /periods/{id}/update {startDate, endDate}`; `GET /periods?space=` → latest or create page; `GET /periods/{id}/data` adds `startDate`, `endDate`, `frequency` to `period`. ### Task 5: Connected transfers

**Files:** Line requests/DTOs/services/repositories (`TransferService` in app/Services/Period/), PeriodCloseService (transfers carried individually), Template expansion with FkTargetSpace, tests `tests/Feature/Period/TransferTest.php`.

Rules (spec §8, §8b): line `targetSpaceId` (egreso only, not own space, 422 otherwise); pay → create/update destination line (`source=transfer`, name 'Desde <espacio>: <nombre>', amount actual ?? estimated, paid, FkTransferFromLine) in the destination period containing the ORIGIN period's StartDate, creating missing destination periods forward from its last period (max 12, else 409 'Creá primero el periodo en <espacio>'; date before its first period → same 409); unpay/delete origin → logical delete destination; amount/target change on a paid origin → update/move destination; destination lines read-only (409 'Se edita desde el espacio de origen'); close: unpaid transfer lines are carried as their own line '↩ <nombre>' keeping targetSpaceId (originals marked carried) and are NOT summed into the general arrastre; reopen undoes them under the same rules (paid or carried onward → 409). Line JSON adds `targetSpaceId`, `transferFromLineId`, `transferFromSpaceName` (nullable). All in one transaction.

- [ ] Steps: tests for every rule above (incl. monthly destination receiving two biweekly origin transfers in the same month; reopen with paid carried transfer → 409) → implement → full suite → commit `feat: connected transfers between espacios`.
